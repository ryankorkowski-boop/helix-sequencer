## Design

A dense, captivating single parade float. Nominal design coordinates X ±56, Y 0–72, Z ±88. This deliberately exceeds an ordinary road-approved envelope; physical parade engineering must rescale and inspect total height, roadway clearance, turning circle, wind loads, outriggers, power, weight and electrical safety. No road-worthiness assertion.

The architecture uses ONLY existing Helix-native xLights families: Poly Line, Custom, Tree 360, and their reusable groups/submodels. The central crossed twin helices expose independent strands, rungs and altitude slices. Nested orbital rings create a prism crown. Seven near-to-far portals, seven perspective arches, four three-ring wheel halos, distributed starburst spinners, two tall mega trees, eight alternating spiral trees, four non-coplanar harmonic matrix planes, four depth grids, twelve side-ribbon rails, four long runways, four elevated twisted-wave rails, three orbital shells, twelve snowflake assemblies and six edge glyphs create continuously readable front, side and elevated vistas. Every item is editable, not a flat background video.

### Hierarchy and audio semantics

- `FLOAT_PRIMARY`: prism core / opposite-handed helices / orbital shells. Guitar/bass counterpoint on the strands, keyboard pitch events at elevation.
- `FLOAT_DEPTH`: tunnel rings / perspective arches / depth grids. Alternating direction and delay from actual source notes, not random motion.
- `FLOAT_RHYTHM`: wheel halos / spinners / percussion stars. Separate kick, snare, hi-hat and cymbal evidence; no whole-display pulse.
- `FLOAT_HARMONY`: mega trees / spiral forest / matrices. Instrument-specific motifs and quantized XYZ travel.
- `FLOAT_FLOW`: ribbon rails / runways / wave rails. Cascading bass and guitar phrases in physical depth.
- `FLOAT_ACCENTS`: snowflakes / edge highlights. Bounded transient accents.

Native group exports are generated by `write_layout` as `HX_ZONE_*`, `HX_DNA_*`, native-family and whole-show memberships. The six macro groups and section priorities in `models/parade_float.py` describe editorial layer combinations; **the standard export has not yet been extended to serialize these six macro names as modelGroups**. Do not confuse documentation priorities with guaranteed runtime group activation.

The original Helix analysis determines instrumental timing, structure, transient intensity and pitch. No lyrics, vocals, invented instrumentation, fixed BPM or random onset are inserted. Existing Helix spatial model schedule uses 12 coordinate slices and source-clock bounded effect windows, delivering directional climbs, convergent spirals, opposing sweeps, harmonic waves, gaps and return motifs. This is distinct from every light simultaneously flashing white.

## Run and acceptance

Source file: [Drive audio](https://drive.google.com/file/d/1VdhX9WvUFgMNhO8HGpziiG-dcInItegJ/view?usp=drivesdk).

After authentically downloading the original MP3 and calculating its SHA-256, a machine with Helix and xLights 2026.18+ can run:

```bash
python -m tools.render_parade_float \
  --audio "/path/to/Polar Prism Parade.mp3" \
  --sha256 "ACTUAL_SHA256_OF_ORIGINAL_AUDIO" \
  --work "/output/parade_float" \
  --xlights "/path/to/xLights"
```

The runner reuses the real Helix master production CLI and existing native writer. It refuses an unverified source file or missing native xLights binary. Real render status comes only from the native receipt, not a synthetic scene demo. Frame-by-frame full-length MP4 verification and video compositing remain follow-up tasks; the existing `render_panel` returns native preview evidence but does not itself perform the complete final advertising MP4 QA. Validate the returned media with full decode, source audio correlation, duration, dimensions, blankness, clipped channels, local contrast, motion patterns, crowd-distance readability, wheel alignment and 3D sight lines before requesting artistic approval.
